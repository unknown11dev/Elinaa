# Setup guide — read this before publishing

This package contains two separate static sites:
- `apology-site/` — the page Yelina opens, with the password gate, your message, 15 screenshots, and reply form.
- `private-inbox/` — your owner-only inbox page.

GitHub Pages hosts static files; it does not itself store/send messages. To make replies reach your inbox, connect both pages to the same Supabase project.

## 1. Create the database
1. Create a project at https://supabase.com/ (you can use its free tier).
2. In **SQL Editor**, run this SQL. It creates a table where anyone can submit a reply, but only the owner account UID you specify can read messages.

```sql
create table if not exists public.yelina_messages (
  id bigint generated by default as identity primary key,
  message text not null check (char_length(message) between 1 and 5000),
  created_at timestamptz not null default now()
);

alter table public.yelina_messages enable row level security;

create policy "Anyone can send a reply"
on public.yelina_messages for insert
to anon, authenticated
with check (char_length(message) between 1 and 5000);

-- Do NOT create a public SELECT policy.
```

## 2. Create your private owner login
1. In Supabase, open **Authentication → Users** and create an owner user with your email and a strong password.
2. Copy that user's **UID**.
3. Run this SQL after replacing `PUT_OWNER_USER_UID_HERE` with the exact UID:
```sql
create policy "Only Fathy can read replies"
on public.yelina_messages for select
to authenticated
using (auth.uid() = 'PUT_OWNER_USER_UID_HERE'::uuid);
```
Only that specific account can read replies through the API. Keep the owner password private.

## 3. Connect both pages
1. In Supabase, open **Project Settings → API** (or **Connect**) and copy the Project URL and `anon` / publishable key. Never use a `service_role` or secret key in a website.
2. Open `apology-site/index.html` and `private-inbox/index.html`.
3. In each file, replace:
   - `PASTE_SUPABASE_PROJECT_URL_HERE` with your Project URL.
   - `PASTE_SUPABASE_ANON_KEY_HERE` with your anon/publishable key.
4. Save the files.

## 4. Publish both on GitHub Pages
Create two separate public repositories, for example:
- `yelina-apology` — upload **the contents inside** `apology-site/` (index.html and assets folder).
- `fathy-private-inbox` — upload **the contents inside** `private-inbox/` (index.html).
For each repository: Settings → Pages → deploy from branch `main`, folder `/ (root)`. Wait for the Pages URL to appear.
The inbox page itself is public to visit, but it requires the owner account sign-in; the messages are protected by Supabase row-level security.

## Important notes
- The password `1/7/2026` is a sweet front-door gate, not strong security: because GitHub Pages is static, someone technically savvy could inspect the HTML and find it. Do not put truly private information on a static page.
- Supabase is not connected until you complete steps 1–3. Until then the reply form will clearly say sending is not connected; it will not pretend a message was sent.
- Screenshots are displayed in the order provided. They are included as images; their text is not separately transcribed.
